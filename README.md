## Overview

This repository contains the complete, reproducible implementation of a **hybrid anomaly detection pipeline** for 5G network slicing environments. The pipeline combines **K-Means clustering** (unsupervised) with a **Multi-Layer Perceptron classifier** (supervised) to perform multi-class intrusion detection on the CICIDS-2017 benchmark dataset.

The key idea is that K-Means first discovers intrinsic traffic structures and generates **pseudo-labels** from unlabeled data, which are then used to train the MLP classifier — enabling the system to learn generalizable decision boundaries without requiring a fully labeled dataset.

### Results at a glance

| Metric | Value |
|--------|-------|
| Overall Accuracy | **97.61%** |
| F1-Macro (primary) | **0.74** |
| F1-Weighted | 0.98 |
| Recall-Macro | 0.97 |
| Attack families detected | **6 classes** |

## Pipeline Architecture

```
CICIDS-2017 Dataset
        │
        ▼
┌─────────────────────┐
│  Data Preprocessing │  → Median imputation, feature exclusion
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│   Label Grouping    │  → 15 subtypes → 6 threat families
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│   Data Splitting    │  → 80% train / 10% val / 10% test (stratified)
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│    Resampling       │  → Bootstrap oversample + BENIGN undersample
└─────────────────────┘
        │
        ▼
┌───────────────────────────────────┐
│        Feature Engineering        │
│  Mutual Information (τ=0.05)      │  → 78 → 60 features
│  MinMax Normalization [0,1]       │
└───────────────────────────────────┘
        │
        ▼
┌─────────────────────┐
│  K-Means (K=7)      │  → Pseudo-label generation
└─────────────────────┘
        │
        ▼
┌─────────────────────┐
│  MLP Classifier     │  → 61-dim input (60 features + Pseudo_Label)
│  (128 → 64 → 32)   │     6-class output
└─────────────────────┘
        │
        ▼
   Validation & Results
```

## Quickstart

### Option 1 — Docker (recommended for full reproducibility)

```bash
# Clone the repository
git clone https://github.com/Joao0015/cicids-anomaly-detection-tutorial.git
cd cicids-anomaly-detection-tutorial

# Build and run the container
docker build -t cicids-tutorial ./docker
docker run -p 8888:8888 -v $(pwd):/workspace cicids-tutorial

# Open the notebook at http://localhost:8888
```

### Option 2 — Local installation

```bash
# Clone the repository
git clone https://github.com/Joao0015/cicids-anomaly-detection-tutorial.git
cd cicids-anomaly-detection-tutorial

# Create a virtual environment (recommended)
python -m venv venv
source venv/bin/activate        # Linux/macOS
# venv\Scripts\activate         # Windows

# Install dependencies
pip install -r requirements.txt

# Launch the notebook
jupyter notebook notebook/pipeline.ipynb
```

## Dataset

This pipeline uses the **CICIDS-2017** dataset, publicly available at:

> [https://www.unb.ca/cic/datasets/ids-2017.html](https://www.unb.ca/cic/datasets/ids-2017.html)

Download the CSV files generated by CICFlowMeter and place them inside the `data/` folder. The notebook expects the following structure:

```
data/
├── Monday-WorkingHours.pcap_ISCX.csv
├── Tuesday-WorkingHours.pcap_ISCX.csv
├── Wednesday-WorkingHours.pcap_ISCX.csv
├── Thursday-WorkingHours-Morning-WebAttacks.pcap_ISCX.csv
├── Thursday-WorkingHours-Afternoon-Infilteration.pcap_ISCX.csv
├── Friday-WorkingHours-Morning.pcap_ISCX.csv
├── Friday-WorkingHours-Afternoon-PortScan.pcap_ISCX.csv
└── Friday-WorkingHours-Afternoon-DDos.pcap_ISCX.csv
```

The notebook automatically draws a **stratified 10% subsample** from each file before concatenation, yielding a working corpus of ~283,000 flow records.

## Threat Families

The pipeline classifies traffic into 6 families, mapped from the original 14 CICIDS-2017 attack subtypes:

| Family | Original Subtypes |
|--------|-------------------|
| `BENIGN` | Benign traffic |
| `DoS/DDoS` | DoS Hulk, DoS GoldenEye, DoS Slowloris, DoS Slowhttptest, Heartbleed, DDoS |
| `PortScan` | PortScan |
| `Brute Force` | FTP-Patator, SSH-Patator |
| `Web Attack` | Web Attack – Brute Force, XSS, SQL Injection |
| `Bot` | Bot |

## Key Design Decisions

- **K=7** was selected semantically (one cluster per traffic family) and validated via Elbow Method + Silhouette Score analysis.
- **Bootstrap resampling** was chosen over SMOTE to avoid interpolation artifacts in network traffic feature spaces.
- **Mutual Information** (τ=0.05) was used for feature selection, reducing the feature space from 78 to 60 attributes while capturing non-linear dependencies.
- **F1-Macro** is the primary evaluation metric to fairly assess performance on minority attack classes.
- All stochastic operations use `RANDOM_STATE = 42` for full reproducibility.
